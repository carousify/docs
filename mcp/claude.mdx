Claude connects to Carousify as a custom connector. You paste one URL, sign in to Carousify and pick a workspace. There's no API key to copy. The connector works in Claude on the web, the desktop app and the mobile apps once it's added.

For Claude Code, you can add the same server from the terminal, or install the [Carousify plugin](/mcp/claude-plugin), which adds the connector together with a skill and commands for carousels and analytics.

## Before you start

- A Carousify workspace on a plan with MCP access, and a role that can connect apps. See [Before you start](/mcp/overview#before-you-start).
- A Claude account. Custom connectors are available on Claude's Free and paid plans; Free accounts can add one custom connector. On Team and Enterprise plans, an owner adds the connector for the organization first (see below).

## Add the custom connector

<Steps>
  <Step title="Open Connectors in Claude">
    In Claude, open **Customize › Connectors**. (In older versions of Claude this was under **Settings › Connectors**.)
  </Step>
  <Step title="Add a custom connector">
    Click **+ Add**, then **Add custom connector**, and fill in:

    | Field | What to enter |
    | --- | --- |
    | **Name** | `Carousify` |
    | **Remote MCP server URL** | `https://api.carousify.com/mcp` |

    Leave the authentication and OAuth options at their defaults: Carousify uses sign-in, and Claude registers itself with Carousify automatically. Don't add an API key or request header.

    {/* SCREENSHOT NEEDED: images/mcp/claude-add-custom-connector.png — Claude › Customize › Connectors › Add custom connector dialog, Name "Carousify", URL https://api.carousify.com/mcp filled in, authentication left at default. Replaces the existing images/mcp/claude-add-custom-connector.png, which shows the old Settings › Connectors dialog. */}

    Click **Add** (Claude may ask you to click **Continue** first to confirm the sign-in method).
  </Step>
  <Step title="Sign in to Carousify and pick a workspace">
    Click **Connect** on the new connector. Claude opens Carousify in a new tab. Sign in if needed (including two-factor authentication if you use it), then:

    - Pick the **Workspace** to connect. Workspaces you can't connect are greyed out with the reason.
    - Check what Claude will be able to do: see your connected accounts; read posts, drafts, schedules and analytics; create, edit and schedule posts; publish and delete posts.
    - Click **Allow access**.

    {/* SCREENSHOT NEEDED: images/mcp/oauth-consent.png — the Carousify consent page (app.carousify.com/oauth/consent/...) for Claude: heading "Claude wants to access your Carousify workspace", "Signed in as …", "You'll be sent back to claude.ai", workspace list with one selected and one greyed out with a reason, the "will be able to" list, Cancel and Allow access buttons. New image, also used on the ChatGPT and Grok pages. */}

    Carousify sends you back to Claude and the connector shows as connected.
  </Step>
</Steps>

<Note>
  Each connection works in one workspace. To use another workspace, disconnect and connect again, choosing the other workspace on the consent screen.
</Note>

### Team and Enterprise plans

On Claude Team and Enterprise, an owner adds the connector once for the organization: **Organization settings › Connectors**, then **Add**, **Custom**, **Web**, and the same name and URL as above. Each member then opens **Customize › Connectors**, finds **Carousify** and clicks **Connect** to sign in with their own Carousify account. Every member acts with their own Carousify role.

## Use it in a chat

In a new chat, click **+** in the message box, open **Connectors** and make sure **Carousify** is turned on. Then try:

- *"What accounts do I have connected in Carousify?"*
- *"Write a LinkedIn post about why agencies use collaboration links to onboard clients, show it to me, then schedule it for Tuesday 9 AM."*
- *"Turn this blog post into a carousel using one of my templates and my default brand kit."*
- *"Design a new carousel template for a product launch, then post it to my company page tomorrow at 10 AM."*
- *"How did my posts do in the last 30 days?"*

Claude asks for your approval before running tools that change things, and you can choose **Allow always** for tools you trust. Carousify also tells Claude to show you the final post and get your confirmation before it publishes, schedules or deletes. See [Permissions and security](/mcp/permissions).

<Tip>
  To use your own photos or PDFs, attach them in the chat or ask Claude for an upload link. See [Upload your own files](/mcp/uploads).
</Tip>

## Claude Code

You have three options in [Claude Code](https://code.claude.com/docs/en/mcp).

**Install the plugin.** The easiest way: it adds the connector plus the Carousify skill and `/carousify:` commands. See [Claude Code plugin](/mcp/claude-plugin).

**Add the server and sign in.** Run:

```bash
claude mcp add --transport http carousify https://api.carousify.com/mcp
```

Then start `claude`, run `/mcp`, select **carousify** and sign in. You pick the workspace in the browser as above.

**Use an MCP API key.** For scripts, CI or machines where you can't open a browser, create a key in **Manage Workspace › MCP** (see [Managing MCP keys](/mcp/overview#managing-mcp-keys)) and pass it as a header:

```bash
claude mcp add --transport http carousify https://api.carousify.com/mcp \
  --header "Authorization: Bearer YOUR_MCP_KEY"
```

<Warning>
  The **Claude** tab on Carousify's MCP page shows a shorter `claude mcp add` command without `--transport http`. Use the commands on this page instead: without `--transport http`, Claude Code doesn't treat the URL as a remote server.
</Warning>

By default the server is added for the current project on your machine only (**local** scope). Add `-s user` to use it in every project, or `-s project` to share it with your team in the repo's `.mcp.json`. For a shared `.mcp.json`, keep the key out of the file with an environment variable:

```json
{
  "mcpServers": {
    "carousify": {
      "type": "http",
      "url": "https://api.carousify.com/mcp",
      "headers": { "Authorization": "Bearer ${CAROUSIFY_MCP_KEY}" }
    }
  }
}
```

Check the connection with `claude mcp list`: Carousify shows **Connected**, or **Needs authentication** if you still need to sign in with `/mcp`.

## Disconnect

- **Claude (web, desktop, mobile):** open **Customize › Connectors**, open the menu on **Carousify** and click **Remove**.
- **Claude Code:** run `claude mcp logout carousify` if you signed in, then `claude mcp remove carousify`.
- **In Carousify:** open **Manage Workspace › MCP › Connected apps** and click **Disconnect** next to Claude. This ends Claude's access straight away. For an API key, turn it off or delete it in **MCP Keys**.

## Troubleshooting

- **The workspace is greyed out on the consent screen.** The reason is shown under the name: the plan doesn't include MCP, or your role can't connect apps. Ask the workspace owner.
- **"This authorization request has expired or was already used."** The sign-in link is valid for 30 minutes. Start again from **Connect** in Claude.
- **Claude says Carousify needs to be reconnected, or tools fail with an authorization error.** Your access was removed (you left the workspace, lost the permission, the plan changed, or someone disconnected the app). Connect again.
- **A post won't publish.** If your role needs approval, Carousify only lets you schedule posts and sends them to Pending Approval. See [How approvals work over MCP](/mcp/permissions#how-approvals-work-over-mcp).
